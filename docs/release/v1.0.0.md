# compress-lib v1.0.0 - Stable

**The API frozen for 1.x, faster on both sides, and three defects found by the 1.0 audit fixed.** v1.0.0 promises no breaking change before 2.0, `forbid(unsafe_code)` and zero runtime dependencies for the whole 1.x line, and stable error codes.

## What's in 1.0.0

- **The 1.x API.** The `io` adapters now say what they do: `io::DecodeReader`, `io::EncodeWriter`, `io::EncodeReader`, `io::DecodeWriter`. `Flush` is exported at the crate root beside `Progress` and `Status`. cargo-semver-checks against 0.9.0 reports the two renames as the only breaking changes.
- **Faster decoding.** The vector and one-shot paths decode into capacity they already reserved before growing; a stream that fitted its first reservation used to reallocate and copy everything for its last bytes. 1.06 to 1.28 times 0.9 on Windows, level with it on Linux and macOS. Matches with periods of 2 to 7 bytes now stay in the fast loop.
- **Faster compression,** up to 1.31 times 0.9 on Linux, macOS, and Windows: a dedicated level-1 loop without hash chains, a block writer with per-block code tables and one eight-byte store per symbol, and a four-byte check that skips chain candidates which cannot win. Levels 2 to 9 produce the same bytes as 0.9; level 1 output is 2.3 to 2.5 percent smaller on JSON and HTML.
- **Fixed: output that depended on how input was split.** At levels 0 and 1 the compressed bytes changed with the sizes of the pieces the input arrived in. They now depend only on the input, the settings, and the flush sequence, and the `roundtrip` fuzz target checks it on every input.
- **Fixed: a truncated stream returned as complete.** When the output vector could not grow, the one-shot `compress` functions returned what they had. They now abort, as growing a `Vec` does; the streaming encoders still return `AllocationFailed`.
- 24-hour fuzz run on the final code (`inflate_raw` 151,357,523 runs, `inflate_split` 101,726,569, `roundtrip` 56,085,017; 309 million in all), no findings.
- 4-hour soak on the final code: 2,098,028 rounds in 4 h 11 min of wall time, heap flat (21,318 bytes live between rounds, peak 1,745,428).
- `docs/PERFORMANCE.md` re-measured on hosted runners, with the rows that still miss the 1.2-times-miniz_oxide bar published and explained.

## Upgrading from 0.9

Rename `compress_lib::io::Reader` to `compress_lib::io::DecodeReader` and `compress_lib::io::Writer` to `compress_lib::io::EncodeWriter`. Nothing else changed in the API.
