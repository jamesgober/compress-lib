# compress-lib v0.5.0 - Feature Complete

**zlib, gzip, format detection, and `std::io`.** v0.5.0 added the framing the web uses around DEFLATE, a way to pick the format at run time, and the `Read`/`Write` adapters. Every feature planned for 1.0 is now in the crate.

## What's in 0.5.0

- `gzip::compress` and `gzip::decompress` (and `_with`): one call. Decoding verifies the CRC-32 and the length, reads every member of a multi-member stream, and keeps the 64 MiB default output cap across all of them.
- `gzip::Decoder` and `gzip::Encoder`: streaming, with every header flag (FTEXT, FHCRC, FEXTRA, FNAME, FCOMMENT). The header CRC is verified when present; the optional fields count against `Limits::max_header` (64 KiB by default) and are stored only when asked (`with_keep_header(true)`), so by default a hostile header costs no memory. Members are capped by `Limits::max_members` (1,024). `with_single_member` and `with_trailing_data` cover files with something after the gzip data. `GzipHeader` writes a name, comment, extra field, time stamp, and OS; by default the header is the same on every platform.
- `zlib::compress` and `zlib::decompress` (and `_with`), `zlib::Decoder` and `zlib::Encoder`: header checks, a window limit (`with_window_bits`), preset dictionaries matched by id, and the Adler-32 verified. HTTP's `deflate` content coding is this format.
- `Format::detect`, the format-generic `Decoder` and `Encoder`, and `compress_lib::decompress`, which detects gzip or zlib and never guesses raw DEFLATE.
- `io` (feature `std`): `Reader` (decompress while reading), `Writer` (compress while writing; `flush` is a sync flush), `Encoder` (read plain, get compressed), `DecodeWriter` (write compressed, get plain).
- Interoperation checked both ways with zlib (through zlib-rs) for zlib and gzip at levels 0, 1, 6, and 9; CPython gzip vectors decode; Python reads the gzip files the `gzip_file` example writes.
- The `framing` fuzz target; the `gzip_file`, `websocket_message`, and `http_body` examples.
