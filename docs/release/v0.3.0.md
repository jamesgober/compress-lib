# compress-lib v0.3.0 - Inflate

**Raw DEFLATE decoding, streaming and bounded.** v0.3.0 shipped the inflater: it takes input and output buffers the caller owns, stops cleanly when either runs out, holds a fixed amount of memory, and checks every output limit before it writes.

## What's in 0.3.0

- `deflate::decompress` and `deflate::decompress_with`: one call for a complete raw DEFLATE stream. Truncated input is `UnexpectedEnd`, bytes after the end are `TrailingData`, and output past `Limits::max_output` (64 MiB by default) is `OutputLimit`.
- `deflate::Inflater`: the streaming decoder. `decompress` and `finish` work on slices; `decompress_vec` and `finish_vec` append to a vector, growing it by doubling but never past the cap. Any split of the input and any output size, down to one byte, gives the same output. After `Done`, `consumed` stops at the stream's last byte, so framing that follows stays with the caller.
- Window bits 8 to 15, enforced exactly: a back-reference past the window is `DistanceTooFar` (RFC 7692 negotiates these sizes, and 8 is a real 256-byte window).
- Limits checked before each output chunk: the absolute cap and, when set, the output-to-input ratio cap, which counts input already taken into the bit buffer so it cannot be gamed by feeding one byte at a time.
- Memory per inflater: about 11 KiB of tables plus the window; the one-shot functions keep no window at all. After construction the slice API allocates nothing (counting-allocator test).
- zlib's acceptance rules, exactly: differential tests compare the verdict and output with zlib (through zlib-rs) on corrupted and random streams, and with miniz_oxide on streams of every level.
- `ErrorKind::AllocationFailed`: vector growth uses `try_reserve`, so memory pressure fails one stream instead of the process.
- Fuzz targets `inflate_raw` (differential against zlib) and `inflate_split` (split invariance), run on every CI push; the `inflate` benchmark; the `streaming` example.

## Measured

On the shared development machine (loaded, so read the ratio, not the absolute numbers), decoding 1 MiB corpora: text 352 MiB/s against miniz_oxide's 322 at level 6, JSON 765 against 581, binary 384 against 277. Hosted-runner numbers against miniz_oxide, zlib-rs, and the flate2 backends arrive with `0.6`.

## What's next

`0.4.0` ships the deflater (levels 0 to 9, window bits 8 to 15, sync, full, and finish flushes) and the RFC 7692 `message` helpers ws-net needs for permessage-deflate.
