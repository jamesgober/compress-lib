# compress-lib v0.7.0 - Hardening

**Every threat attacked, the engines soaked for hours, two defects fixed.** v0.7.0 added the attack tests, ran the soak, wrote the threat model down, and fixed two defects a WebSocket peer could trigger in 0.6.

## What's in 0.7.0

- `tests/attacks.rs`: one test per threat in the plan, written as the attack. Bombs of 32 MiB and 80 MiB of zeros, in raw DEFLATE, zlib, gzip, and through format detection, stop at the output cap (and the streaming engine never writes a byte past it); a ratio bomb under the cap stops at the ratio cap while ordinary text passes the same limits; malformed Huffman descriptions, distances before the data or past a 512-byte window, a megabyte of empty stored blocks, 5,000 empty gzip members, and a megabyte gzip file name are all refused in bounded time; flipped checksum bytes never pass; truncated streams are never complete; smuggled trailing bytes are refused; one-byte output buffers decode a megabyte in linear time; input built to fill every hash chain stays within the chain limit at level 9.
- The compression side channel, measured: without context takeover, the compressed size of an attacker's guess does not depend on a secret sent earlier; with takeover it does, which is why takeover is off by default.
- `docs/SECURITY.md`: the threat model, each defence with its cost and its test, and guidance on limits, `Limits::unlimited()`, and compressing secrets.
- A 24-hour fuzz run of the decoder targets on the fixed code is clean so far and finishes before 0.9.
- A 4-hour soak on the fixed code: 446,443 random round trips through every format, level, window, and flush pattern, with the live heap flat at 21,318 bytes and a peak of 1,731,540 bytes.
- A nightly fuzz workflow: every target for ten minutes.
- Fixed: a WebSocket message fed one compressed byte per call cost quadratic CPU, because vector decoding zero-filled the whole message so far on every call (a 16 MiB message took about 15 seconds; now milliseconds). Each call now costs its own input and output.
- Fixed: `message::Decompressor` accepted a message whose last block was cut short, and with context takeover then decoded the next message as garbage. A message must now end on a block boundary after its `00 00 FF FF` tail (`UnexpectedEnd` otherwise).
- `wipe()` on the inflater, the deflater, and both `message` engines: the history and every buffer zeroed, spare capacity included, when a connection that carried secrets ends (threat T-15), as ws-net's `wipe` needs.

## What's next

`0.8.0` is the alpha: the consumer paths (WebSocket permessage-deflate, HTTP content codings, response compression) exercised end to end, and what they find fixed.
