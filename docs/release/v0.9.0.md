# compress-lib v0.9.0 - Beta

**The API 1.0 will freeze, and the audit that goes with it.** v0.9.0 finished the API and documentation audit, wrote the stability promise down, and closed the 24-hour fuzz run of the decoder.

## What's in 0.9.0

- The API audit: `io::Encoder` is now `io::EncodeReader`, the pair of `io::DecodeWriter`, so the reading compressor no longer reads like the format-generic `Encoder`; the `io` constructors are `#[must_use]`; every public item has a runnable example (229 doc tests).
- `docs/STABILITY-1.0.md`: what 1.0 promises (semantic versioning, stable error codes, `forbid(unsafe_code)` and no runtime dependencies for all of 1.x, an MSRV policy, deprecation before removal, security support) and the audit, item by item.
- `docs/ARCHITECTURE.md` (how the engines, framing, and helpers fit together) and `docs/PLATFORM-NOTES.md` (what is checked on which target, determinism across platforms, `no_std`).
- 24 hours of fuzzing per decoder target (`inflate_raw`, `inflate_split`) on the 0.9 decoder, 78,459,234 and 21,727,907 runs, with no findings.

## Upgrading from 0.8

Rename `compress_lib::io::Encoder` to `compress_lib::io::EncodeReader`. Nothing else changed in the API.

## What's next

1.0.0, when James gives the go: the API frozen until 2.0. Brotli follows in 1.1 (decode) and 1.2 (encode).
