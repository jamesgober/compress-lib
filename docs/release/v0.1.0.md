# compress-lib v0.1.0 - Scaffold

**The repository and the plan.** v0.1.0 set up the crate in the portfolio template and wrote down the design before any code. There is no codec in this release; it also claimed the name on crates.io.

## What is compress-lib?

<strong>compress-lib</strong> compresses and decompresses raw DEFLATE (RFC 1951), zlib (RFC 1950), and gzip (RFC 1952), with the per-message rules of WebSocket permessage-deflate (RFC 7692). The engine is sans-IO with caller-owned buffers, memory is fixed per engine, and every decoder enforces output caps while it decodes, so decompression bombs cost at most the cap. No `unsafe` code, no third-party runtime dependencies.

## What's in 0.1.0

- The crate manifest: edition 2024, MSRV 1.85, no dependencies, `Apache-2.0 OR MIT`, feature `std` on by default (`no_std` with `alloc` without it).
- The crate root: `VERSION`, `unsafe_code` forbidden, missing docs denied, and `unwrap`/`expect`/`panic` denied in library code.
- CI on Linux, macOS, and Windows, each on x86_64 and aarch64, on stable and 1.85; checks for 32-bit, big-endian, wasm32, and bare-metal `no_std` targets; Miri on a little-endian and a big-endian target; a job that fails if the crate gains a runtime dependency; `cargo package`; `cargo audit` and `cargo deny`.
- `dev/PLAN.md`: purpose, scope, requirements, the design of the inflater and deflater, the API with item ids and the version of each, a parity matrix against miniz_oxide, zlib-rs, flate2, and zlib, fourteen threats with their attack tests and costs, performance targets, the testing plan with thirty edge cases, open decisions, ideas, and the decision log.
- `dev/DIRECTIVES.md` (engineering law and definition of done) and `dev/ROADMAP.md` (phases 0.2 to 1.0 with exit criteria).

## What's next

`0.2.0` locks the public API in `docs/API.md` and ships the first code: the error and limit types and the CRC-32 and Adler-32 checksums. `0.3.0` ships the raw DEFLATE inflater with streaming, window bits 8 to 15, and decompression limits.
