# compress-lib v0.2.0 - Design Lock

**The API, written down, and the first code.** v0.2.0 wrote the complete planned public API into `docs/API.md`, each item with the version it arrives in, and shipped the pieces every codec stands on: the checksums, the error type, the decoder limits, and the compression levels.

## What's in 0.2.0

- `docs/API.md`: Tier 1 one-call functions, the streaming `Inflater` and `Deflater`, the RFC 7692 `message` helpers, zlib and gzip framing, format detection, the `std::io` adapters, and brotli after 1.0.
- `checksum::crc32` and `Crc32`: CRC-32 as gzip and zip use it, slicing-by-16 with tables built at compile time, streaming, resumable from a stored value, and combinable in O(log n).
- `checksum::adler32` and `Adler32`: the zlib checksum, four lanes with deferred modulo, streaming and combinable in constant time.
- `Error` and `ErrorKind`: every kind the codecs through 0.5 return, each with a stable code (`compress.output_limit`) for logs and metrics and a message that says what to do; errors carry the compressed-input offset where they were found; `From<Error> for std::io::Error`.
- `Limits`: a 64 MiB output cap by default, an optional output-to-input ratio cap with a floor, caps on gzip header fields and members, and `Limits::unlimited()` for trusted data.
- `Level`: 0 to 9 with zlib's meaning.
- Property tests for every checksum against a bit-at-a-time reference, split invariance, and combining; criterion benchmarks for both checksums.

## What's next

`0.3.0` ships the raw DEFLATE inflater: streaming with caller buffers, window bits 8 to 15, limits checked before every output chunk, and `deflate::decompress`.
